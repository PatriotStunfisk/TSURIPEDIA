# 釣りガイドの情報設計

入口と記事URLは `/guide` と `/guide/[slug]` に統一。QUICK GUIDE専用のURLや独立カテゴリは作らない。

## 記事を追加する

既存の `GuideArticle` へ本文と `editorial` を一緒に記述し、記事集を `all-guides.ts` に登録する。

```ts
editorial: {
  articleType: 'QUICK GUIDE',
  topic: 'tackle',
  gearTags: ['rig'],
  parentGuide: 'aji-sabiki-depth',
}
```

- `GUIDE`：準備から実践まで、テーマを体系的に扱う記事。
- `QUICK GUIDE`：一つの疑問に結論から答える記事。文字数だけでタイプを決めない。
- `topic`：釣り方、仕掛け・道具、魚の扱い、料理・保存、基礎、安全、季節・釣り場の7目的。
- 既存216記事の分類は `guide-editorial.ts` に明示。既存の `category` は互換性のため維持するが、記事タイプとは別物。
- 新規記事は `editorial` を本文の横に記述。分類が欠けると登録時にエラーになる。
- 魚・釣法タグは既存 `related` の正確なURLから取得。直接の関係がない記事では、明示した親GUIDE、または関連GUIDEの関係を補助的に使用する。魚名の部分一致で関連付けない。
- 親GUIDEは明示指定を優先。指定がなければ、同じ魚・釣法や直接リンクから体系記事を選ぶ。共通テーマだけでは親にしない。
- 親からのQ&Aと子からの戻りリンクは共通ページで生成。表示上限を超える疑問は絞り込み一覧へ案内する。
- 読了時間は冒頭の結論・本文・表・手順等の表示テキストから500字/分で算出。URLやJSONキーを文字数に含めない。

## 検索とSEO

同じ検索フォームから両タイプを検索。目的・魚・釣法・道具・タイプは任意の追加条件。1ページ24記事、ページ移動時も条件を保持する。魚の別名slugは共通エイリアスへ正規化する。

既存記事のURLと本文は保持。canonicalは既存記事URL、一貫したOG/Twitter metadataとsitemapを維持。人気・PVの架空ランキングは作らない。

## 品質

新規QUICK GUIDEは「結論→理由→条件→選び方→関連情報」を基本とする。同じ検索意図をキーワード違いで追加しない。今回の初期記事は長いサビキ仕掛け、結び目の引っかかり、エギングの横風。

道具の案内は回答の後に既存共通Amazon機能を使用。`uolink-22`とPR表記を維持する。魚図鑑・釣法・MAPへは実在する共通データからリンクする。
