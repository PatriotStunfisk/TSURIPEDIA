# 2026-09-17 ホーム軽量化

## 原因と変更

ホームの魚カードが詳細ページ向けの FishVisual を参照し、Three.js を含む約691KBのchunkが初期JSに含まれていた。魚ページ専用の補助処理もroot layoutに存在した。基本7魚種のPNGは表示幅に対して大きく、ロゴ2枚も合計1.10MBだった。

- ホーム魚カードをサーバーコンポーネント HomeFishImage に分離。基本10魚種・カード・リンク・見た目を維持。
- canonical画像から320/640px WebPを生成。原本は変更せず、srcsetと実際の1/2/4列レイアウトに合うsizes、lazy、幅・高さを指定。
- ヘッダー・フッターのロゴも表示サイズに合うWebPを追加。
- ホーム・ヘッダー・フッターの遷移を通常のaリンクにし、クライアントルーターの準備・prefetchを待たずHTMLで遷移する。各詳細ページの操作は維持。
- FishPageEnhancer は /fish 配下だけで実行。MAP・QUEST・魚3Dは各機能のページに残す。
- 外部フォントは初期表示で使っていない。全画面loading overlayやwindow loadへの操作依存は確認されなかった。
- 再生成：`node scripts/export-home-images.cjs`（Sharpが外部の場合はSHARP_MODULEを指定）。featuredを変更した際は画像manifestも再生成し、テストで欠落を検出。

## 計測

同じ端末の本番build、改善前cb291e0との比較。JSはHTMLが参照する初期scriptをHTTP取得し、同じgzip設定で圧縮した値。Vercel実転送のBrotliやキャッシュ込み実測とは異なる。

| 対象 | 改善前 | 改善後 |
| --- | ---: | ---: |
| 初期JS（非圧縮） | 1,322,330 B | 568,896 B |
| 初期JS（gzip換算） | 373,981 B | 174,665 B |
| 基本7魚種の画像ファイル合計 | 11,475,134 B | 362,086 B（640px版） |
| ヘッダー・フッターロゴ合計 | 1,099,479 B | 42,836 B |
| CSS（非圧縮） | 73,157 B | 73,157 B |

画像は同じ7魚種を比較したファイルサイズであり、lazyによる初期転送量の測定ではない。残る3魚種もWebP化し、基本10魚種の640px版合計は570,364 B。

## 低速・表示検証

ローカルHTTPプロキシで画像とJSの応答を45秒保留し、HTML/CSSは先に返す故障・遅延条件を使用。Safariで画像未完了のホームから魚図鑑への遷移を確認。ホーム要求04:57:45.713 UTC、魚図鑑要求04:57:56.585 UTCで、45秒の画像解放前に遷移。これは操作した時刻を含むログであり、11秒のTTIという意味ではない。

改善前もこの条件では遷移できたため、報告された操作停止の完全再現・待ち時間の比較はできていない。IABの遅延試験では操作API側がページ読み込みを待つため、その待機時間は性能結果として採用しない。

1280px PCと390pxスマホ表示を確認。スマホの実カード幅にsizesを修正。LCP・INP・CLSの前後の信頼できる測定値や実ユーザーのCore Web Vitalsは未取得。転送量削減だけから指標の改善値を推測しない。
