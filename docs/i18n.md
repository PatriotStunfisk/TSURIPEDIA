# Japanese and English content

Japanese URLs are unchanged. `app/(ja)` is a route group, not a URL segment. It retains the existing Japanese root layout and pages. `app/en/layout.tsx` supplies a separate `lang="en"` root and `app/en/[[...path]]/page.tsx` statically renders the English routes. Language changes use ordinary anchors so they also work before hydration.

## Authoring

Shared identifiers, taxonomic names, media, seasons, relationships and location coordinates remain in the existing fish/method/guide/spot registries. Do not copy a location dataset for a locale.

English editorial overlays live in `lib/i18n/fish.ts`, `methods.ts`, `guides.ts` and `cooking.ts`. Guide entries adapt existing guide IDs for visitors to Japan. Cooking entries reuse original recipe IDs and photographs. `common.ts` contains small labels and prefecture names. No translation service is called at request time.

`pages.ts` derives English route generation and metadata. `route-manifest.json` is the deliberately small client-safe list of translated article IDs used by the language switch; keep it synchronized when adding translations. Tests detect drift. Spot route IDs are obtained from the shared registry on the server, rather than copying thousands of IDs into the language switch.

English coverage at this release: 112 fish, 50 methods, 13 guides, cooking for the initial 10 fish, all shared spot detail routes and an English map. The map sends a compact representation of shared records, not long location descriptions or both languages' editorial content. Leaflet is dynamically imported. Fish cards remain native links with lazy images and reserved image dimensions.

## Incomplete translations are explicit

Japanese place names are intentionally retained for local recognition. Detailed, location-specific access notes and many linked official references remain Japanese and are clearly labelled. Their English summaries do not establish permission to fish. Recipes beyond the first ten species, individual Japanese recipe URLs, other guides, gear/product copy, 3D viewer controls, catch submission/login and QUEST remain Japanese. English spot pages show concise community-catch summaries and link explicitly to the Japanese full feed/posting UI. No untranslated English URL is advertised for those pages.

## SEO and language navigation

Each English page has its own English canonical. Published Japanese/English pairs have reciprocal `ja`, `en` and `x-default` alternatives in metadata and sitemap. Japanese is the default. No English canonical points to the Japanese page. Unknown untranslated article routes return 404. On untranslated Japanese pages the language switch says “English home”; it does not pretend that the article was translated.

The shared language switch imports only the route manifest. Do not import `pages.ts`, fish profiles or full translation dictionaries into it. English MAP query filters use the existing fish/method IDs, are retained in the URL and survive language switching.

## Further locales

Add a locale overlay and layout with the correct HTML `lang`, then extend the small route/alternate helpers and sitemap only for completed translations. Keep IDs and images in the shared registries. There is no need to introduce a runtime translation API or copy spot records for Chinese/Korean.

## Verification

Run TypeScript, lint, all Node tests and production build. `tests/i18n.test.cjs` checks registry coverage, manifest synchronization, guide references, reciprocal sitemap entries, cooking eligibility and image paths. Verify Japanese/English navigation, English fish search, MAP filters/preview, mobile header and existing Japanese routes in the browser. Public HTML must contain meaningful content and native links before JavaScript runs.
