# 最近の釣果と外部ソース

## 利用者向け
- `/catches`: HOTな釣り場、最近報告のある魚、ユーザー投稿、公式・外部情報を区別して表示。
- `/spots?fish=tachiuo&recent=30days`: その魚の直近30日以内の報告がある地点だけ表示。静的な「狙える魚」と実際の報告を混同しない。
- MAPは集計だけ取得し、写真・本文は地点選択後に既存APIで取得。リングは緑＝最近の報告、橙＝HOT。アニメーションは追加しない。
- サイズは既存の `size_cm`（数値、0より大きく500以下）を再利用。任意入力。魚は既存の名前・別名を検索できる。

## HOT判定
`lib/catches/activity.ts` の `hotPolicy` で調整する。
日本時間の釣行日を基準に当日〜6日前は3点、7〜13日前は1.5点、14〜29日前は0.5点。30日前以降・未来日は除外。
同一投稿者／取得元・同日は最大1回分、同一主体は期間中最大6点。複数主体、情報源、公式情報、魚種数を加点。
HOTには直近7日3件以上、直近7日に独立した2主体以上、12点以上が必要。公式の転載は元URLを同一化して重複除去する。匿名旧投稿は同一主体と扱う。
件数は魚の匹数ではなく報告件数。魚上位は直近30日。HOTは過去期間との増加率や釣れる確率を示さない。

## 軽量化
既存ユーザー投稿の直近30日・必要なスカラー列だけをサーバーで読む。1,000件ずつ取得し、10万件を超える場合は不完全な集計を返さずエラーにする。
魚・釣法・期間はDBクエリ側でも絞り込み、集計結果のみサーバーキャッシュ5分、公開APIキャッシュ最大約2分。投稿・削除・管理操作でサーバーキャッシュを無効化する。
ブラウザには投稿者ID・本文・全履歴を返さない。今後利用量が増えたらDBの日別集計へ置換できる共通モデルになっている。

## 外部データ接続
取得条件を確認したソースを `lib/catches/sources.ts` に登録する。
鳴尾浜海づり広場・とっとパーク小島の公式HTMLを接続。日付と魚種の構造化された一覧行だけを抽出し、独自の定型文と出典リンクを表示する。集計のサイズ範囲は個体サイズへ変換しない。記事本文・写真は保存しない。
公式／外部ともHTTPSの許可ホスト・固定エンドポイントに限定（JSONまたは取得元専用HTML解析）。転送は許可ホスト内で最大2回、各リクエスト10秒、1MB、最大500件。本文・写真・GPSは取り込まない。
JSON形式: `{ "catches": [{ "id": "publisher-id", "date": "YYYY-MM-DD", "fishSlug": "aji", "spotSlug": "既存ID", "summary": "許諾された240字以内の要約", "sourceUrl": "https://出典URL", "methodSlug": "sabiki", "sizeCm": 20 }] }`。
日付は公開日ではなく釣行日。fish/spot/methodは既存IDを検証し、曖昧な紐付けは推測せずスキップする。取得元ごとのアダプターで既存registryから正規化して接続する。
RSSは本文や公開日を釣果・釣行日と誤認しやすいため、汎用XML収集は未実装。許諾済みRSSが決まったら元別の変換器を追加する。

## DBと運用
1. `supabase/catch-activity.sql` をレビューして適用。外部キャッシュ・実行ログだけを追加。ユーザー投稿と認証・RLSは維持。
2. `CATCH_EXTERNAL_ENABLED=true`、`CRON_SECRET` をサーバー環境変数に設定。秘密値はリポジトリに保存しない。
3. 条件を確認したソースを登録・有効化する。
4. `vercel.json` にUTC21時・12時（日本時間6時・21時）の2つの日次ジョブを定義。プランの上限と既存Cron数を公開前に確認する。Hobbyでは時刻が最大約1時間ずれる可能性があり、厳密時刻を保証しない。
5. `/admin/catches` の「外部釣果の更新状況」で成功／失敗、新規件数、未対応件数、更新日時を確認。API `/api/catches/imports` は既存管理者認証必須。

Cronは未設定のSecretを許可しない。ソース単位で失敗を分離し、DBの一意キーで同一URL・日付・魚・地点の再取得を重複登録しない。外部キャッシュは60日前、実行ログも60日前を削除する。ユーザー投稿は削除しない。
本番DB適用・環境変数設定・外部ソース許諾と本番Cronの実行確認は、ローカルbuildの成功とは別に確認する。

参考: https://vercel.com/docs/cron-jobs/usage-and-pricing 、https://anglers.jp/terms

## MAPプレビュー
PCは左側、760px以下は下部にコンパクトなカードを表示。選択変更時だけカードの実測矩形を除いた領域の中心へ同じズームでpanする。手動で地図を動かした際は引き戻さない。カードのサイズが変化したときは再調整する。外部情報を個人のUOLINK投稿件数として表示しない。

とっとパークは施設公式トップからリンクされた公開釣果表のみ取得。minnaga.comの汎用robotsルールで対象パスの禁止はなく、専用UOLINK User-Agentで1実行1ページのみ。学習用GPTBot等の拒否ルールとは区別し、写真・本文・利用者名を保存しない。Shift_JISを復号し、数値単独cmのみ個体サイズとして扱い、範囲表記はサイズ集計へ入れない。

外部情報の公開表示はユーザー指定により「外部情報」のみ（取得元のブランド名や引用文・出典リンクを表示しない）。元URLとsource IDはDB内部に保持し、重複防止・再取得・管理に使う。匹数は構造化された「匹数」欄のみ採用し、「2釣果」などの投稿件数を匹数に転用しない。
