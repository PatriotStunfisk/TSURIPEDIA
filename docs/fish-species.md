# 魚種プロフィールの管理

## 追加の入口

1. `lib/fish-species/<slug>.ts` を作成し、`defineFishSpecies` にプロフィールを渡してdefault exportします。既存のプロフィールを形の参考にできますが、解説の内容を別魚種から流用しないでください。
2. `lib/fish-species/index.ts` にimportと `fishSpecies` 配列の1項目を追加します。配列順は魚図鑑の並びに反映されるため、既存項目の順序は保ってください。

この2ファイルの編集で、従来のデータ窓口へプロフィールが反映されます。ルートごとの登録は不要です。

## 項目

型の定義は `lib/fish-species/types.ts` にあります。`base` 以外は任意です。情報がない項目を埋めるためだけに文章やページを作らないでください。

| 項目 | 内容と反映先 |
|---|---|
| `base` | slug・名前・学名・旬・サイズ・説明・釣法等。図鑑一覧、詳細、metadata、sitemapの共通情報。 |
| `base.methodSlugs` | 曖昧な釣法名に頼らず、既存釣法slugを明示する任意の配列。 |
| `base.guideSlugs` | 追加で紹介したい既存GUIDEのslug。記事側の魚リンクの逆引きと合流。 |
| `base.relatedSlugs` | 関連魚の既存slug。名前表記に依存せず関連先を指定。 |
| `detail` | 分類・生態・特徴・旬の補足・初心者Tips・釣りの要点・安全・食味・豆知識。 |
| `launch` | 見分け方、キャッチコピー、画像メモ、補足の釣法リンク・関連魚名・エリア。汎用ページの追加解説にも反映。 |
| `cooking.prep` | 下処理の手順。料理一覧・魚ごとの料理ページへ反映。 |
| `cooking.recipes` | レシピslug・名前・画像・要約・材料・手順・Tips。料理ページとsitemapへ反映。 |
| `tableGuide` | 既存の専用料理カードを維持するための表示上書き。省略すればレシピから料理カードを生成。 |
| `featuredOrder` | `launch` を持つ魚のトップ掲載順。未指定の追加魚は既存掲載魚の後。 |

魚名とslugは `base` だけに登録します。`cooking` 内に重複して書く必要はありません。
レシピから自動生成されるカードは、レシピの名前・画像・要約・slugを使います。
既存の専用カードには異なる編集文章があるため、意味の異なる文章を機械的に統合せず `tableGuide` に保持しています。

## 互換性と依存関係

`types.ts` → `define.ts` → 魚種別ファイル → `index.ts` → 既存データ窓口 → `fish-registry.ts` → 各ページ、の順に依存します。
プロフィール側から `data.ts` や `fish-registry.ts` をimportすると循環するため、使用しません。

- `data.ts`: 全魚種のプロフィールから基本情報を提供。
- `fish-details.ts`: 詳細が登録されたプロフィールから詳細情報を提供。
- `launch-fish.ts`: プロフィールから重点魚種と追加解説を生成。
- `cooking-data.ts`: プロフィールから料理データを生成。
- `fish-registry.ts`: 従来の取得関数を維持し、料理情報・料理カードも提供。

タチウオ・アジのページに直接書かれた専用料理紹介や、アジの専用解説ブロックは今回の移行対象外です。
専用ページの画像選択や3D表示も既存のままです。

## 検証

`npm run test:content`、`npx tsc --noEmit`、`npm run lint`、`npm run build` を実行し、追加魚と主要魚のページをデスクトップ・モバイルで確認します。
魚slugの重複、レシピslugの形式・重複、存在しないレシピを参照する専用カードはプロフィールの検査で検出します。

移行テストは既存の文章・画像参照・配列順が変わっていないことをハッシュで確認します。新しい魚の追加だけでは更新不要です。
既存魚の解説を意図的に改訂するときは、差分を確認したうえで対応する期待値も更新してください。

全25魚種の基本情報と、既存の23魚種の詳細を魚種別ファイルに移行済みです。アナゴ・イサキには元から詳細解説がないため、空の詳細は追加していません。互換データ窓口へ魚種を手動で追記しないでください。
