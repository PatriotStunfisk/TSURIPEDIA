# UOLINK QUEST

## 魚を追加する

魚図鑑と同じ `lib/fish-species/<slug>.ts` と index 登録を利用する。QUEST用の魚一覧への二重登録は不要。

`lib/quest/catalog.ts` が基本プロフィールの名前・slug・months・サイズ・難易度・釣法、共通レジストリの料理/GUIDE導線、画像/GLBの有無から薄いクライアント用データを組み立てる。ゲーム環境に対応する釣法を持つ魚だけが参加する。現時点では25魚種中22魚種。淡水のアユ・ニジマス・アマゴは対応環境/釣法の整備後に参加できる。

通常は追加パラメータ不要。調整が必要な魚だけ、プロフィールに次を設定する。

```ts
quest: {
  rarity: 1,         // 1〜5。抽選重みに影響
  fightPower: 20,    // 1〜100。巻いたときのテンション増加
  biteRate: 0.9,     // 0〜1
  escapeRate: 0.05,  // 0〜1。フッキング時の失敗率
  xp: 30,
  swimSpeed: 1.1,    // 0.1〜3：遊泳演出
  wariness: 0.2,     // 0〜1：誘い過ぎの警戒
  approachSpeed: 18, // 5〜50：棚一致時の接近
  biteWindowMs: 4500,// 800〜10000：食い込みの猶予
  stamina: 60,      // 20〜100
  runPower: 50,     // 1〜100：走りによる負荷
  habitats: ['osaka-bay-pier'],
  methods: ['sabiki'],
  sizeRange: [10, 40], // base.sizeと同じ単位。通常cm、マダコなどはkg。省略時はbase.sizeから派生
},
```

`enabled: false` で参加を保留できる。存在しない釣法/環境、範囲外の数値は検証で失敗する。釣法・環境を狭める指定は実際に対象魚が残ることをテストする。months はJSTの現在月に対する抽選の重みに利用し、ゲーム上の確率を現実の釣果予測として表示しない。

## 構造

- `lib/quest/habitats.ts`: 大阪湾堤防・沖、砂浜、岩礁帯、明石、和歌山の6環境と釣法、MAP検索語。
- `catalog.ts`: サーバー側で既存魚/釣法データを統合。料理本文や全GUIDEをクライアントに配信しない。
- `engine.ts`: キャスト→アタリ→合わせ→ファイト→釣果。乱数・時刻を注入できる純粋関数。失敗/タイムアウトから再キャスト可能。
- `progress.ts`: 捕獲、初魚種、大型魚、ミッションのXP。8ミッション、レベル、称号。デイリーはJST午前0時更新。
- `storage.ts` / `QuestProvider.tsx`: version付き保存形式、localStorage、タブ内メモリへのフォールバック。
- `components/quest`: スマホ対応の画面。釣果から魚・釣法・釣具・MAP・料理・GUIDEへ移動。
- `/gear?method=<slug>`: 既存の釣法タックルを再利用。
- `/spots?q=<検索語>`: 既存MAP一覧の検索を初期化。
- `/quest/play?fish=<slug>`: その魚に対応した釣法/環境を初期選択（狙った魚の確定排出ではない）。

## 保存と表示

ログイン不要。キーは `uolink:quest:v1`。累計捕獲・魚別最大サイズ・釣法/環境別の捕獲魚種・XP・受取済み報酬・直近200件・直近30日を保持する。再受取と同一釣果の重複登録を防ぐ。不正/将来バージョンのデータは上書きせず警告してメモリで続行。ブラウザのデータ消去、別端末への移動には対応しない。同時タブの更新は通知と直前読込で補助するが、サーバー保存のような排他保証はない。

未捕獲魚は名前を隠し、捕獲後に記録と詳細を解放。GLBは利用者が3Dを選んだ時だけロードし、未提供なら2D。読み込み失敗時も2Dへ戻せる。既存魚詳細の3Dカメラ設定は維持し、QUESTだけ共通Viewerの `contain` を利用する。

`/quest`・`/quest/play`・`/quest/missions` をsitemapに登録。個人状態の `/quest/collection`・`/quest/profile` はnoindex。旧 `/game` はURLを残して `/quest` へリダイレクトする。公開導線は新QUESTへ統一。

## 水中プレイ（2026-09）

サビキは群れの棚へ仕掛けを合わせる。エギングは2回程度のしゃくりで誘い、フォール後の抱き込みを掛ける。カワハギは誘いを止めた後、つつきから持ち込みに変わる短い猶予で掛ける。残り釣法は共通の接近・バイトを使う段階的な実装。

水中は正式2D画像と軽量アニメーションが基本。既存GLBは「水中を3Dで見る」で明示的に読み込み、共通Viewerの `swim` を使う。既存魚詳細のカメラ・操作の既定値は変更しない。GPU資源、イベント、アニメーションは解除する。

魚はスタミナがある間、走りと休みを繰り返す。走っている最中の巻き取りは張力が増え、ドラグを緩めると負荷と寄せる力がともに減る。放置・早合わせ・食い込みの見逃し・糸の張り過ぎから再キャスト可能。体長から重量を推定して実測のように表示しない。マダコは元データが重量のためkg表示。既存version 1の保存値は変更しない。

`lib/fish-images.ts` は既存7魚種の正式画像URLを持ち、専用ページとQUESTが共有する。新プロフィールは `media.image` が正。画像のない簡易魚種は従来のシルエット表示を保ち、別魚種の画像を流用しない。現在、QUEST 22種中13種に正式画像がある。
